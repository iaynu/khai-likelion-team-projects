# 백엔드 아키텍처 개요 (ARCHITECTURE.md)

이 문서는 **Backbone 백엔드**의 고수준 아키텍처를 설명하며, 다양한 컴포넌트들이 어떻게 상호작용하여 AI 분석 및 시뮬레이션을 제공하는지 요약합니다.

## 시스템 구성 요소

백엔드는 확장성과 관심사 분리를 위해 설계된 분산 아키텍처를 따릅니다.

1.  **FastAPI 웹 서버**:
    *   리액트 프론트엔드로부터 들어오는 REST API 요청을 처리합니다.
    *   매장 검색이나 메타데이터 조회와 같은 동기적 작업을 관리합니다.
    *   고부하 작업이 필요한 경우 Redis 브로커에 메시지를 발행하여 이벤트를 트리거합니다.

2.  **Redis 메시지 브로커**:
    *   FastAPI 서버와 Celery 워커 사이의 통신 브릿지 역할을 합니다.
    *   작업 큐를 저장하고 작업 결과 상태를 추적합니다.

3.  **Celery 워커 (Worker)**:
    *   Redis에서 작업을 가져와 비동기적으로 실행합니다.
    *   CPU 또는 LLM 자원이 많이 필요한 작업(시뮬레이션, Y-Report 생성)을 처리합니다.
    *   데이터베이스와 직접 통신하여 결과 데이터를 영속화합니다.

4.  **데이터베이스 계층**:
    *   **PostgreSQL**: 운영 환경의 데이터 보존을 위해 사용됩니다.
    *   **SQLite**: 로컬 개발 및 빠른 테스트를 위해 사용됩니다.
    *   **SQLAlchemy**(비동기 ORM)와 **Alembic**(마이그레이션)을 통해 관리됩니다.

## 데이터 흐름 및 처리 파이프라인

### 1. X-Report 파이프라인 (진단)
- **흐름**: `프론트엔드 -> /x-reports (POST) -> FastAPI -> LLM (GPT) -> 데이터베이스 -> 반환`.
- **로직**: 2단계 파이프라인을 사용합니다. 먼저 GPT가 리뷰 및 매장 원천 데이터를 분석합니다. 두 번째로, 9개의 구체적인 실행 전략을 구조화된 JSON 형식으로 생성합니다.
- **캐싱**: 불필요한 LLM 호출을 방지하기 위해 `(store_id, snapshot_version, prompt_id)` 조합을 기반으로 결과를 캐싱합니다.

### 2. 시뮬레이션 및 Y-Report 파이프라인 (예측)
- **흐름**:
    1.  `프론트엔드 -> /simulations (POST) -> FastAPI -> Redis 메시지 발행`.
    2.  `Celery 워커 -> simulation_task 실행 -> 에이전트 기반 시뮬레이션 -> DB에 결과 저장`.
    3.  `프론트엔드 -> /y-reports (POST) -> FastAPI -> Redis 메시지 발행`.
    4.  `Celery 워커 -> y_report_task 실행 -> 비교 분석 -> 최종 마크다운 보고서 생성 -> DB 저장`.
- **상태 추적**: 프론트엔드는 `/jobs/{id}` 엔드포인트를 주기적으로 호출(Polling)하여 진행률(0-100%)을 확인하고 완료 또는 실패 여부를 감지합니다.

## 핵심 설계 원칙

| 원칙 | 구현 내용 |
|---|---|
| **비동기 우선 (Async First)** | API 응답성을 유지하기 위해 시간이 오래 걸리는 작업은 워커로 오프로드합니다. |
| **원자적 트랜잭션 (Atomic TX)** | 보고서 생성과 그에 따른 전략 생성을 단일 DB 트랜잭션으로 묶어 데이터 무결성을 보장합니다. |
| **JSON 우선 파싱** | LLM 응답을 JSON으로 우선 처리하며, 실패 시 텍스트 폴백을 지원하여 UI 카드의 데이터 무결성을 100% 보장합니다. |
| **뷰 서비스 패턴 (View Service)** | DB 모델을 프론트엔드에 보내기 전, 서비스 레이어에서 UI 최적화 DTO(Data Transfer Object)로 변환합니다. |
| **계층 분리** | Router -> Service -> Repository -> Model 구조를 통해 코드 유지보수성을 확보합니다. |
